# 媒体访问控制与密钥轮换

本文记录上传图片、上传音频和 TTS 合成音频的存储格式、下载鉴权、配置与恢复边界。

## 威胁模型

媒体目录中可能包含题干、提示材料或与患者作答相关的敏感内容。仅依赖 UUID 文件名不能形成可靠访问控制：

- URL 可能出现在浏览器历史、截图、代理日志或错误报告中；
- 永久 URL 一旦泄露，无法在不改文件名的情况下失效；
- 直接静态目录映射绕过 Token、角色和业务资源检查。

系统因此不再把 `MEDIA_ROOT/images` 和 `MEDIA_ROOT/audio` 注册为公开静态目录。

## 下载流程

1. 已认证用户通过上传、套题或结果 API 获取媒体信息。
2. `MediaUrlService` 识别内部路径并生成：

   ```text
   https://api.example.com/images/{uid}/{file}
     ?expires={Unix秒}
     &signature={Base64URL(HMAC-SHA256)}
   ```

3. 签名覆盖完整稳定路径和过期时间：

   ```text
   /images/{uid}/{file}\n{expires}
   ```

4. `MediaController` 在读取磁盘前验证：

   - 媒体类型只能是 `images` 或 `audio`；
   - uid 和文件名只能包含安全路径字符；
   - 链接尚未过期；
   - HMAC 使用常量时间比较且与路径、过期时间一致。

5. 验证通过后以内联资源返回，并设置：

   - 正确的图片/音频 Content-Type；
   - `Cache-Control: private`，最长不超过链接剩余有效期；
   - `X-Content-Type-Options: nosniff`；
   - Spring Resource Range 支持，保证音频播放和拖动进度可用。

缺少签名、链接过期、路径或签名被篡改时返回 403；签名有效但文件不存在时返回 404。

## 持久化规范

数据库只保存无主机、无查询参数的稳定相对路径：

```text
/images/doctor-id/uuid.png
/audio/doctor-id/uuid.mp3
```

以下响应边界会重新生成短期签名：

- 上传图片/音频；
- TTS 合成音频；
- 套题及其题目；
- 题目评分规则中的提示、选项、场景和指令物品媒体；
- 作答历史中的题目快照。

写入题目时，后端会把当前签名 URL 或旧版绝对 URL 重新规范化为稳定路径，并要求内部媒体路径中的 uid 与题目 owner 一致；医生不能通过手工构造路径引用其他账号的私有媒体。外部 HTTPS 图片以及 Flutter `assets/` 路径保持原样，不经过本地媒体代理。

## 为什么不是 owner-only 下载

题目媒体通常由医生上传，但发布后需要由患者读取。若按目录 owner 直接拒绝跨用户读取，患者将无法正常做题。

当前授权模型是：

- 上传、套题和结果 API 先通过 Token、角色及资源归属校验；
- 这些可信 API 才发放短期能力链接；
- 图片控件和原生音频播放器随后无需携带 JWT 即可读取；
- 链接泄露后的最大暴露时间由 TTL 控制。

这不等同于永久公开 URL。需要更强即时撤销能力时，可以在后续版本引入媒体授权记录或一次性 nonce。

## 配置

| 环境变量 | 必需 | 说明 |
|---|---|---|
| `JWT_SECRET` | 是 | 至少 32 字节；默认同时作为媒体签名密钥 |
| `MEDIA_SIGNING_SECRET` | 否 | 独立媒体 HMAC 密钥，设置后可与 JWT 分开轮换 |
| `MEDIA_URL_TTL_SECONDS` | 否 | 1～86400 秒，默认 3600 秒 |
| `APP_PUBLIC_BASE_URL` | 生产必需 | 完整 HTTPS 后端基础地址，如 `https://api.example.com` |
| `MEDIA_ROOT` | Docker 已配置 | 媒体持久化根目录 |

后端会拒绝使用少于 32 字节的媒体签名密钥启动。仓库中的测试配置使用专用假密钥，不得复制到生产。

## 密钥轮换

1. 生成新密钥：

   ```bash
   openssl rand -hex 32
   ```

2. 更新密钥系统或 `.env` 中的 `MEDIA_SIGNING_SECRET`。
3. 重启全部后端实例，确保没有实例继续签发旧密钥链接。
4. 旧链接立即失效；客户端重新请求套题、结果或文件列表获得新链接。
5. 验证无签名、旧签名、篡改签名均返回 403，再销毁旧密钥。

轮换不会修改 MongoDB 或媒体文件，因为签名从未持久化。

## 备份与恢复

- 备份 MongoDB 中的稳定路径和 `media-data` 卷，两者必须来自一致的维护窗口。
- 签名密钥通过独立密钥系统备份，禁止放入普通数据归档。
- 恢复到新域名时设置新的 `APP_PUBLIC_BASE_URL`；无需批量改写数据库 URL。
- 恢复后抽查套题、提示音、选择图片、TTS 音频和历史题目快照能否生成并访问新签名链接。
