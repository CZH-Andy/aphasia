# 作答记录完整性与归档

本文档描述 `examResult` 数据的写入协议、并发控制、历史快照和兼容边界。作答记录属于医疗相关敏感数据，不能把客户端提交的整份 JSON 直接视为权威事实。

## 服务端权威字段

创建记录时，客户端只提供 `examId`。服务端从已发布套题生成并锁定以下信息：

- 记录 `id`、患者 `ownerId`；
- 套题名称、测评/康复类型；
- 亚项和子项结构及名称；
- 开始时间、删除状态和初始 `revision`；
- 初始总分与空作答列表。

更新时客户端不能修改这些字段。服务端还会：

- 按套题中的题目顺序校验每次新增的作答；
- 每次请求最多追加一道题，已保存的作答不能被回退或替换；
- 校验题目结果类型及 `0 <= finalScore <= fullScore`；
- 重新计算子项、亚项和整份测评的汇总分数；
- 完成测评时检查所有子项已答完或已触发终止规则；
- 根据套题中的 `DiagnoseByScoreRange` 规则重新生成诊断文本；
- 使用服务器时间写入开始和完成时间。

客户端提交的 `examName`、`resultText`、层级 `finalScore`、层级名称、`isRecovery`、`isDisabled` 和时间值不会直接落库。

## 并发更新

每条记录包含单调递增的 `revision`：

1. 创建成功返回 `revision: 0`。
2. 更新请求必须携带最近一次响应中的 `revision`。
3. 服务端使用 `_id + ownerId + isDisabled + revision` 原子更新。
4. 更新成功后 revision 加一。
5. revision 过期、记录已完成或进度回退时返回 HTTP 409。

客户端收到 409 后不得盲目重试旧请求，应重新获取记录或回到历史记录页确认最终状态。

## 原始作答归档

历史记录会保存解释作答所需的原始载荷：

| 题型 | 归档字段 |
|---|---|
| 录音题 | `audioContent`（ASR 识别文本） |
| 选择题 | `choiceSelected` |
| 指令题 | `actions` |
| 书写题 | `writingContent`（OCR 识别文本） |
| 寻物题 | `clickCoordinate` |

每道已答题还保存不含医生 ownerId 的 `sourceQuestionSnapshot`，包括题干、题型、媒体地址和当时的评分规则。这样原题随后被删除或调整时，新产生的历史记录仍能解释。

旧记录如果没有快照，读取时仍会尝试查询当前题目；题目已不存在时显示“原问题已删除”占位信息。

## 兼容与迁移

- 已完成的旧记录可以继续查询和删除。
- 旧记录缺少 `revision` 时按 revision 0 处理；第一次合法更新后进入新协议。
- 旧的进行中记录只有在客户端还能提供原 `examId` 且结构仍与已发布套题一致时才能续写。
- 无法确定原套题的旧进行中记录不应通过名称猜测关联，应保留备份后重新创建作答记录。
- 新客户端必须发送 `examId`；缺失时服务端返回 400。

部署前应备份 MongoDB。若需要批量迁移旧记录，迁移脚本必须先生成只读审计报告，再按 `_id` 更新，禁止按 `examName` 自动猜测套题。

## 当前边界

服务端已经对记录归属、顺序、并发、分数范围、汇总分数和诊断文本负责，但单题 `finalScore` 仍由客户端的题型评分逻辑产生。恶意客户端仍可能在合法分数范围内伪造单题得分。

下一阶段应基于本次已归档的原始作答载荷，在服务端实现各题型评分器；涉及 ASR、OCR、流畅度和文本相似度的题型还需要保存第三方调用版本、模型版本和可审计响应摘要。

## 隐私与保留

`audioContent`、`writingContent`、动作和坐标可能构成医疗相关个人数据。生产部署必须定义：

- 最短必要保留期；
- 患者导出、删除和撤回授权流程；
- 医生及运维人员的访问审计；
- 备份加密、恢复审批和到期销毁；
- 第三方 ASR/OCR/LLM 数据保留策略。

不要把包含真实作答的 MongoDB 导出、日志或测试夹具提交到 Git。
