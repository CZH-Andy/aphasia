# 安全边界与账号管理

本文档记录当前安全约束、部署前置条件和仍未关闭的风险。它是运维与后续开发的安全基线，不应只依赖 README 中的演示说明。

## 账号与权限

- 公开接口 `POST /api/register` 只允许创建患者账号（role 1）。
- 客户端即使伪造 `role: 2`，DTO 校验和服务层也会拒绝或降权。
- 医生账号不得通过公开注册创建，只能由受控的管理员流程、审核后的数据导入或演示种子创建。
- 所有套题写操作除了要求医生角色，还必须验证当前医生是该套题的 `ownerId`。
- 更新题目时以 URL 中的 `questionId` 为权威值，并验证题目的 `ownerId`，不信任请求体中的 id。

当前项目还没有管理员后台。生产部署若需要新增医生，必须建立可审计的审批流程；不要恢复“注册页面选择医疗人员”的旧行为。

## 上传文件

- 上传文件由服务器生成 UUID 文件名，不使用客户端提供的原始文件名。
- 图片根据文件头仅接受 PNG、JPEG、GIF、WebP。
- 音频根据文件头仅接受 WAV、MP3、OGG、WebM、M4A。
- 单文件上限为 10 MB。
- Docker 中上传媒体保存在 `media-data` 卷，容器重建不会再直接丢失。
- 上传目录不再由 Spring 静态资源处理器直接暴露。
- 后端仅通过带 `expires` 与 HMAC `signature` 的短期 URL 下载媒体；缺少签名、过期、路径或签名被篡改时返回 403。
- 套题、历史结果和题目快照返回前会重新签名内部媒体 URL；数据库只保存稳定相对路径，不保存临时签名。
- 医生写入题目时，内部媒体路径的 uid 必须与题目 owner 一致，不能借题目配置重新签发其他账号的媒体链接。
- 签名密钥必须至少 32 字节，默认复用 `JWT_SECRET`，生产可用 `MEDIA_SIGNING_SECRET` 独立轮换。

患者需要读取医生发布题目中的媒体，因此下载不是简单的“目录 owner 才能访问”。权限在经过 Token/角色校验的套题、上传和结果 API 发放签名链接时建立，随后链接在有效期内作为短期能力凭证使用。详细边界、轮换和恢复流程见 [媒体访问控制与密钥轮换](MEDIA_ACCESS_CONTROL.md)。

## 生产部署必须满足

1. 前后端只通过 HTTPS 暴露；当前 Compose 的 HTTP 端口仅用于本机开发和演示。
2. `JWT_SECRET` 使用至少 32 字节随机值，禁止留空。
3. 配置 `APP_PUBLIC_BASE_URL=https://...`，避免签名媒体 URL 回退到开发用 HTTP 地址。
4. MongoDB、Redis 增加认证与网络访问控制。
5. 明确配置生产 CORS 域名，不使用宽泛的通配模式。
6. 对登录、注册、上传、OCR、ASR、LLM 接口增加限流与调用配额。
7. 配置日志脱敏，禁止记录密码、Token、完整患者对话和第三方密钥。

## 医疗与第三方服务边界

系统会把语音、手写或对话数据发送到讯飞、百度、阿里云和 SiliconFlow。使用真实数据前必须完成：

- 患者知情同意；
- 最小化采集和必要字段脱敏；
- 第三方数据处理与保留策略确认；
- 删除、导出和撤回授权流程；
- 访问审计和异常调用告警。

当前 LLM 输出是研究性辅助筛查结果，不是经过临床注册或充分外部验证的诊断结论。前端和报告不得把它描述为医生诊断的替代品。

## 仍需优先关闭的风险

- 服务端已锁定作答记录归属、顺序、修订号、汇总分数和诊断文本，并保存原始作答载荷；但单题分数仍由客户端产生，恶意客户端仍可能在满分范围内伪造得分。详见 [作答记录完整性与归档](RESULT_DATA_INTEGRITY.md)。
- 媒体下载已有短期签名校验，但尚无自动生命周期清理、引用计数和患者撤回授权后的即时缓存清除。
- 登录密码仍通过自定义 HTTP header 提交，应迁移到标准 JSON 登录请求体。
- 百度部分调用尚未统一设置连接、读取和总超时。
- 尚无统一限流、审计日志、Token 主动吊销和管理员账号管理。
